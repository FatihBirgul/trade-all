# Trade AI 2.0 — Emergent frontend API contract

**Date:** 2026-10-21. **Version:** `v2-backend-1` / `v2-product-analysis-2`.
This contract describes implemented routes, not a UI mock. OpenAPI:
[`V2_OPENAPI.json`](V2_OPENAPI.json), generated from the actual FastAPI app.
Every JSON file under [`v2_examples/`](v2_examples/) is generated by calling the
in-process backend with explicitly labelled fixtures. They are **not live prices**.
The outage example injects a failed live provider; it contains no substitute prices.

## Local launch and authentication

From `backend`, install `requirements-v2.txt` in a dedicated virtual environment.
Set a private random `V2_API_TOKEN` of at least 24 characters. Example PowerShell:

```powershell
$env:V2_API_TOKEN = (python -c "import secrets; print(secrets.token_urlsafe(32))")
python start_v2.py --database ../local_data/v2-live.sqlite --mode live
```

The launcher binds **127.0.0.1:8002 only**. It does not expose a public server,
install a Windows service, change firewall settings, or enable phone access.
For a separate demo database, explicitly use `--mode fixture` and a different path.
An existing DB cannot switch between live and fixture mode. Foreign/prototype DBs
are refused; no MongoDB migration or user-data reset is performed.

Base URL: `http://127.0.0.1:8002/api/v2`. All V2 routes require:

```http
Authorization: Bearer <V2_API_TOKEN>
Content-Type: application/json
```

Interactive schema: `/docs`; machine schema: `/openapi.json`. Do not embed a real
token in committed frontend source. There is currently one local owner token,
not a multi-user login/session API. Local CORS permits `localhost:3000` and
`127.0.0.1:3000`. Additional/private-network origins need an explicit later setup.
The same router can be mounted in V1 by explicitly setting `V2_DB_PATH`,
`V2_API_TOKEN`, and `V2_DATA_MODE`; standalone V2 needs no MongoDB or AI keys.

## Formats and UI rules

- Money, prices, quantities and rates are **decimal strings**. Keep them as
  strings in API requests/state; accounting calculations belong in the backend.
  Do not convert the ledger to binary floating point for balance calculations.
- `*_ms` are UTC Unix epoch **milliseconds**, not seconds. Convert to local time
  only for display. A candle close timestamp is exclusive.
- `data_mode` is `live` or `fixture`, fixed for this runtime/database. A fixture
  badge must remain visible on analysis, portfolios, charts and performance.
- `price_time_ms` is the last closed current-timeframe bar; it is not a ticker.
  `age_ms` is age **at analysis time**. On history screens recompute display age
  from `price_time_ms`, label the timeframe, and keep the historical decision intact.
- `direction=WAIT` has `levels=null`. Do not draw executable entry/SL/TP lines,
  manufacture an entry, display a success probability, or enable AUTO placement.
  Technical values may be null when mathematically unavailable; show “unavailable”.
- `levels.target_3=null`: TP3 is not implemented and must not be invented.
- The router selects analytical eligibility; heuristic evidence is not a verified
  profitable strategy. News/calendar/flow feeds are explicitly unavailable here.
- Request validation rejects extra fields. Client clocks cannot override the
  analysis as-of time. Fixture event ingress is disabled in live mode.

Analysis request (use `data_mode=live` against a live runtime):

```json
{
  "symbol": "BTCUSDT",
  "market": "crypto_spot",
  "timeframe": "1H",
  "timeframes": ["15m", "4H"],
  "data_mode": "fixture",
  "risk_portfolio": "AUTO",
  "auto_paper": false,
  "idempotency_key": "ui-analysis-unique-request-001"
}
```

Current timeframe is always included. Supported timeframes are `1m`, `5m`, `15m`,
`1H`, `4H`, `1D`; at most five additional timeframes. Each batch must have at least
250 closed, aligned, fresh candles for the built-in strategies. No symbol, spot/perpetual,
venue, source, or future-bar mixing is allowed. MTF current evidence is removed
before Confluence because the same current indicators are already counted there.

`risk_portfolio` chooses which account's balances/pause/risk are evaluated. A paused
AUTO account does not block a separately requested MANUAL analysis.
`auto_paper=true` requires `risk_portfolio=AUTO`; it creates a **pending virtual**
candidate only after all gates pass. It is never a real-money order. AUTO also
de-duplicates by symbol/venue/timeframe/strategy/closed bar, even with a new request key.

The full JSON analysis example includes ID/version, source/contract/mode, requested
timeframes, price timestamp/age, per-timeframe QC, regime, router/reason, indicators,
market quantity/tick rules, MTF, de-duplicated supporting/conflicting evidence,
direction, conditional levels, cost-aware risk, expiry, warnings and safe scenarios.
The empty TP3 field is intentional. Levels are conditional and tick-rounded;
execution fees/spread/slippage are applied separately by the paper model.

Chart candles come from the exact immutable snapshot used by that analysis,
not a new price request. They include `source_record_id`, `snapshot_only=true`,
source/provider/instrument/price-kind/real-volume/mode, original `as_of_ms`, and
closed OHLCV bars with decimal-string prices/volume and UTC timestamps. Refresh
by creating a new analysis, not by relabelling a historical snapshot as live.
Quality-invalid analyses return 409 `CANDLE_SNAPSHOT_UNAVAILABLE`; an absent
timeframe returns 404; corrupt provenance returns 503 `STORAGE_CORRUPT`.

### Paper accounting/execution model

- AUTO and MANUAL each start with **10,000 virtual USDT**, isolated balances,
  reservations, positions, history, pause flags and performance. No deposit,
  withdrawal, reset, real exchange key or real order endpoint exists.
- Runtime policy `demo-spot-conservative-1` is an uncalibrated demo preset:
  trade risk 0.5%, total 3%, correlation group 1.5%, daily realized loss plus open
  stop reserve 3%, notional 90%, max five exposures, net TP1 R:R >= 1.2. It is not
  an investment recommendation or a verified profitability claim.
- Execution model `next_closed_bar_touch_worst_edge_v1`: only subsequent aligned,
  closed 1m bars can fill. Pending entry triggers when the bar touches the entry
  range; reference is the worst entry edge, plus adverse costs. No entry on a bar
  that opened through invalidation. No fill from an already-started historical bar.
- Simulated per-side fee 5 bps, total quoted spread 2 bps, slippage 1 bp per side.
  These are paper assumptions, not a verified user's exchange commission. Parameters
  are saved on each order. Partial fills are capped at 1% of bar volume per account;
  this is a declared liquidity model, not order-book certainty.
- Cash debits include entry notional + fee; exits credit proceeds minus fee.
  Cost basis includes entry fees. Realized PnL includes allocated entry costs and
  exit costs. Unrealized PnL uses the latest observed closed mark and includes
  remaining entry cost basis; future exit fees are not deducted until execution.
- TP1 closes half, stepped down; TP2 closes the remainder. A gap through a stop
  uses the worse opening price, not a guaranteed stop fill. Partial fills/exits,
  cancellation, expiry, pending closes and current positions survive restart.
- Same-bar stop/target ordering or an entry-bar exit is `ambiguous`; no win or
  favorable intrabar order is invented. The account pauses new entries. Risk and
  cash remain reserved until explicit close/cancel/review. Ambiguous cases are
  excluded from win/loss statistics even if later manually resolved.
- If the opening price is already through the stop, that stop precedes later
  intrabar target touches. A volume-limited stop sets `stop_triggered=true` and
  `status=exit_pending`; remaining quantity continues exiting on subsequent bars,
  even after a rebound. New entries pause until the protective exit is complete.
- New risk is blocked when an account has stale open marks or unprocessed old
  pending risk. `/paper/poll` must catch up consecutive bars; gaps are rejected.
  Binance historical recovery now uses exact consecutive windows, at most 300
  closed 1m bars per symbol per tick. Longer outages recover over multiple ticks;
  12-hour recovery including restart is tested. Every page is fully validated
  before its ledger/outbox transaction. `PAPER_RECOVERY_IN_PROGRESS` (409) means
  progress committed but another poll is needed before new risk. Missing history
  or unsupported historical adapters return `PAPER_HISTORY_INCOMPLETE` /
  `PAPER_HISTORY_UNAVAILABLE` (503), keeping stale risk blocked. Latest-source
  freshness/identity is validated first; old history never hides an outage.
- Mutations use atomic SQLite transactions. Duplicate requests return their
  original response; read the GET endpoints for current state. Same idempotency key
  with different content is HTTP 409. Same candle with changed OHLCV is a conflict.

## Portfolio, position, transaction and performance fields

- Portfolio: `portfolio_id`, quote/mode, seed/cash/reserved/available/equity,
  realized/unrealized PnL, realized loss today, open/pending counts, `paused`.
- Position: IDs/account/symbol/mode/status, quantity, average entry, cost basis,
  mark price/**mark_time_ms**, PnL, invalidation, targets, open time, pending closes,
  `stop_triggered`, `ambiguity_seen`.
- Transaction: unique persistent ID, account/order/position/event IDs, action kind,
  quantity, execution price, fee, cash delta, realized PnL, time and mode.
- Performance: separate account rows with closed positions, wins/losses, historical
  ambiguity count (including later manually closed cases), win rate or null when undefined, PnL/equity and fees. No fabricated
  sample size, return curve, forecast or success probability is generated.

## Error contract

```json
{"error":{"code":"RISK_REJECTED","message":"Paper risk gate: portfolio_risk_limit"}}
```

| HTTP | Codes / frontend handling |
| --- | --- |
| 401 | `UNAUTHORIZED`: request a valid local token, never log it |
| 403 | `FIXTURE_DISABLED`: never post fixture candles to a live runtime |
| 404 | `ANALYSIS_NOT_FOUND`, `ORDER_NOT_FOUND`, `POSITION_NOT_FOUND`, `PORTFOLIO_NOT_FOUND` |
| 409 | `IDEMPOTENCY_CONFLICT`, `AUTO_SIGNAL_ALREADY_USED`, `RISK_REJECTED`, `ORDER_NOT_CANCELLABLE`, `EVENT_CONFLICT`, `OUT_OF_ORDER_EVENT`, `MARKET_EVENT_GAP`, `INSUFFICIENT_CASH`, `UNRESOLVED_PAPER_EXIT` |
| 422 | `VALIDATION_ERROR`, `DATA_MODE_MISMATCH`, `INVALID_AUTO_ACCOUNT`, `INVALID_PAPER_SIZE`, `INVALID_CLOSE_SIZE`, `INVALID_MARKET_EVENT` |
| 503 | `PROVIDER_UNAVAILABLE`, `MARKET_DATA_INVALID`, `MARKET_UNAVAILABLE`, `STORAGE_UNAVAILABLE` |
| 500 | `V2_INTERNAL_ERROR`: inspect GET state, then retry the same key; internal exception details are not returned |

Scanner conflicts: `WATCHLIST_LIMIT` (409). A tick can return HTTP 200 with
`status=blocked`, or a failed job reason `SCANNER_PAUSED` / `SCANNER_STALE_JOB`;
the UI must display that state rather than treating HTTP success as job success.
`STORAGE_CORRUPT` is HTTP 503 and requires review; it never auto-reseeds balances.

On storage failure no half-updated balance is committed; retry the **same** key.
On WAIT show the reason/warnings and freshness; do not convert WAIT into an order.

Watch request:

```json
{"symbol":"BTCUSDT","timeframe":"1H","enabled":true,"auto_paper":false}
```

Up to ten watch entries, supported spot symbols, timeframe `5m/15m/1H/4H/1D`.
Scanner defaults **paused**, with AUTO placement **off per watch**. Use
`python start_v2.py --database ../local_data/v2-live.sqlite --mode live --scanner`
to opt into a single cooperative 60-second worker. No worker starts merely by
importing/mounting the router. Without that flag the API tick remains available.
After adding watches, explicitly unpause to start work. Graceful worker shutdown
persists pause. Pausing stops future polling/analyses; it does not liquidate or
erase positions. Display stale marks while paused, and poll before resuming risk.

Each tick prioritizes existing paper exposures; failed price recovery blocks new
analyses. It processes at most two new watch analyses. A durable 120-second lease
prevents concurrent workers/ticks. Jobs identify mode/provider/watch/last closed
bar; repeat ticks do not re-analyze that job. An interrupted current job recovers
using the same analysis idempotency key; old unfinished jobs become `skipped_stale`
instead of using historical data to place new candidates. New committed candidates
are blocked if pause/lease/closed-bar boundary changed during provider I/O.

`running/completed/failed/skipped_stale` are job states. `completed` means analysis
saved, and may contain a WAIT; it never means a profitable trade. Failed jobs are
not retried in a tight loop; a new closed bar allows the next attempt. Jobs and
outbox survive restart. Notifications are immutable **pending**, with
`delivery_service=not_configured`; no email, push or delivery acknowledgement API
exists. History retention/compaction is not implemented. Notification rows for
paper fills are produced by scanner polling; explicit event/poll calls retain the
ledger journal but do not claim scanner notification delivery.

## Analysis engine extension — second development task

Two additive fields preserve earlier consumers: `technical_methods` and
`strategy_setups`, with empty defaults on older records. Methods include causal
FVG, 2-left/2-right confirmed BOS/CHoCH, closed reclaim sweep and a rolling 20-bar
real-volume typical-price VWAP proxy. Tick/absent/zero volume does not create VWAP.
This is not session/anchored or exact trade-tape VWAP. Each result exposes
availability/version/as-of and diagnostic geometry; no probability is produced.

The four active versioned strategies are `trend_momentum_v2` (continuation, v2),
`range_mean_reversion_v2`, `confirmed_breakout_v2`, and `failed_breakout_v2` (v1).
See [V2_EMERGENT_HANDOFF.md](V2_EMERGENT_HANDOFF.md) for exact entry/invalidation/
WAIT rules. Opposite confirmed candidates veto priority; same-direction precedence
is sweep > breakout > range > trend. Generic external equal-priority specs retain
WAIT. All existing portfolio/cost/risk gates remain in force, and spot short is
still unavailable. Other-timeframe opposing evidence vetoes new strategies.

New strategies use three deduplicated conceptual buckets (price_structure,
momentum, volume). FVG/BOS/sweep must not be counted separately; VWAP/volume are
one bucket. These categories do not claim statistical independence. Existing
trend composite/Confluence gating is retained. `strategy_setups` carries versions,
parameters/requirements, warm-up, reason, direction, Wilder RSI diagnostics and
conditional candidate geometry. Only top-level direction/levels/risk authorizes
paper placement; nested levels cannot override WAIT. Legacy `indicators.rsi14`
is a different simple rolling RSI and is not the setup's Wilder RSI14.

Full actual fixture responses: [range_setup.json](v2_examples/range_setup.json),
[breakout_setup.json](v2_examples/breakout_setup.json),
[sweep_setup.json](v2_examples/sweep_setup.json). These are generated with explicit
export/test providers, not public fixture_case requests or live inputs. Existing
fixture_case=range remains a no-confirmation WAIT example.

Additional WAIT reasons include `strategy_confirmation_missing`,
`strategy_reward_risk_gate` (candidate), `opposing_strategy_conflict`,
`mtf_strategy_conflict`, `strategy_direction_conflict`. HTTP 200 does not imply
eligibility. Scanner recovery returns `status=blocked` with a recovery reason.
No new API endpoints or token mechanism were introduced.

[Windows setup/verified backup/restore/private-network design](V2_WINDOWS_SETUP.md)
includes a manual PowerShell launcher and rotating local runtime logs. No Windows
service, BFF/session or phone-network configuration has been installed/tested on
the user's PC. The Emergent handoff spells out the local UI + server-side proxy
requirement; a remote preview cannot call the user's loopback backend directly.
